# MVP Activity Database Fields

## Purpose

This document defines the smallest database contract needed to demonstrate:

```text
Create activity → save through FastAPI → persist in the database → load in the library
```

The MVP is intentionally limited to creating and displaying basic activities.
It does not require the advanced gamification configuration shown in the design
mock-up.

## MVP scope

The MVP supports:

- creating an activity;
- saving it as a draft;
- persisting it through the FastAPI service;
- listing saved activities;
- loading activities after a page refresh;
- displaying basic activity information in the frontend.

## MVP activity table

| Field | Type | Required from frontend? | Database requirement | Description |
|---|---|---:|---:|---|
| `id` | Integer | No | Required | Internal database identifier generated by the database. |
| `external_id` | String | No | Required and unique | Stable API/integration identifier generated by the backend for the demo. |
| `creator_external_id` | String | No | Required | Creator identifier supplied by the demo identity until authentication exists. |
| `creator_role` | `EDUCATOR` or `EMPLOYER` | No | Required | Role supplied by the demo identity until authentication exists. |
| `title` | String | Yes | Required | Short activity name. |
| `description` | Text | Yes | Required | Instructions or explanation of the activity. |
| `category` | String | Yes | Required | Basic grouping label such as `Learning`, `Career`, or `Community`. |
| `final_xp` | Integer | No | Required, default `0` | Stored XP value. Advanced XP calculation is not part of this MVP. |
| `status` | `Draft`, `Active`, or `Inactive` | No | Required, default `Draft` | New activities are saved as drafts. |
| `created_at` | Date/time | No | Required | Set by the backend when the activity is created. |
| `updated_at` | Date/time | No | Required | Set by the backend when the activity changes. |

## MVP create request

The frontend should only need to submit:

```json
{
  "title": "Attend Career Workshop",
  "description": "Attend the workshop and submit notes.",
  "category": "Learning"
}
```

The backend supplies or defaults:

```text
external_id
creator_external_id
creator_role
final_xp = 0
status = Draft
created_at
updated_at
```

## MVP API flow

```text
POST /v1/activities
        ↓
activities table
        ↓
GET /v1/activities
        ↓
Activity library
```

## MVP exclusions

The following are intentionally excluded from the MVP database contract:

- detailed XP factors;
- recurring activity rules;
- challenge tables;
- achievement tables;
- student completion records;
- cosmetic rewards and inventory;
- publishing approval workflows;
- activity version history;
- authentication-owned creator identity.

These can be added after the basic persistence flow is working.
